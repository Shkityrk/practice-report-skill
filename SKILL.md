# practice-report: методичка → план → выполнение → скриншоты → отчёт

Универсальный процесс для любой практической/лабораторной работы. Отчёт здесь — **побочный продукт реально выполненной
работы**: тексты и цифры берутся из логов настоящих запусков, а не из воображения, поэтому студент может всё показать и
объяснить на защите. Скилл не привязан к теме: специфика дисциплины живёт в `PLAN.md` конкретной работы.

Справочники читать по мере необходимости:
`references/workflow.md` (этапы), `references/report-structure.md` (разделы и шаблоны текста),
`references/safety.md` (изоляция, что спрашивать), `references/screenshots.md` (техника кадров),
`references/lessons.md` (общие грабли — прочитать до реализации), `references/docs-markup.md` (разметка PLAN/notes и другие скиллы).

## Что нужно на входе

1. **Методичка** (PDF/docx) и папка работы (обычно `…/pr-N/`).
2. **Образец оформления** — прошлые отчёты пользователя и, если есть, документ с требованиями к оформлению. Если
   требований нет — прямо сказать и опереться на прошлые отчёты (их оформление по умолчанию уже в `scripts/report_lib.py`:
   Times New Roman 14, интервал 1.5, поля 3/1.5/2/2, подписи рисунков и таблиц, номера страниц).
3. **Данные для титульного листа**: ФИО студента, группа, руководитель, дисциплина, институт/кафедра. Значений по
   умолчанию нет — спрашивать у пользователя. По умолчанию работа делается **только для владельца сессии**; отчёты для других
   людей — только по явной просьбе и с их данными, без копирования чужих ФИО из старых файлов.
4. **Ограничения среды**: что нельзя трогать (рабочие конфигурации, логины, ключи, данные).

## Рабочий процесс (шесть этапов)

Идти по порядку; между этапами 1 и 2 остановиться и показать план с вопросами — это дешевле, чем переделывать.

**0. Приём.** Прочитать методичку целиком: `scripts/pdf_to_text.py методичка.pdf` печатает текст и сохраняет PNG страниц.
Команды/код/конфигурации в методичках часто вставлены КАРТИНКАМИ — открыть PNG этих страниц (Read) и переписать
содержимое. Прочитать лучший прошлый отчёт и его генератор, чтобы уловить структуру, длину и стиль.

**1. План.** `python3 scripts/new_practice.py <pr-N> --no N --student-surname … --student-short "…" --group … --discipline … --supervisor …`
создаёт каркас (`PLAN.md`, `env.sh`, `notes/`, `report/{config.json,shots.py,build_report.py}`). Заполнить `PLAN.md`:
таблица требований T1…, окружение и риски, известные проблемы методички, список скриншотов, чек-лист. Показать
пользователю вместе с вопросами: ФИО/группа, **варианты «по фамилии/номеру»** (если что-то в методичке зависит от
студента — спросить, не угадывать), недостающие документы, разрешения. Дальше — только после ответа.

При необходимости инициализируй venv.

**2. Окружение и безопасность.** Следовать `references/safety.md`: разведка только чтением → копия и хеш рабочих файлов →
изолированное окружение `env.sh` → проверка изоляции. Установки, скачивания (в т.ч. репозиторий из методички) и любые
действия вне папки работы — только после явного «да». Python-зависимости: `scripts/setup_env.sh` (venv
`~/.cache/practice-report-venv`: python-docx, playwright, pymupdf; системный Python не трогается).

**3. Реализация.** Один раз выполнить работу руками и убедиться, что она работает (поведение, а не статус «запущено»).
Методички часто содержат устаревшее или ошибочное — исправлять минимально, **каждое отступление записывать** в
`PLAN.md` (таблица «что в методичке → что сделано → почему»): оно попадёт в отчёт.

**4. Скриншоты.** Заполнить `report/shots.py` (на `scripts/shots_lib.py`): чистое состояние → этапы строго в порядке методички
→ кадры `01-….png…`; команды настоящие, секреты маскируются (`redact`, подмена подписи). Запускать в фоне с логом; пока идёт —
писать текст отчёта. Затем **посмотреть ключевые PNG глазами** и переснять неудачные точечно (`references/screenshots.md`).

**5. Отчёт.** Заполнить `report/build_report.py` на `scripts/report_lib.py` (`Report.title_page/toc/heading/sub/para/
figure/table/code/bullets/sources/save`). Разделы: титул → содержание → ЦЕЛЬ → ХОД РАБОТЫ (по этапам методички + «Отличия
от методички») → ОТВЕТЫ НА ВОПРОСЫ → ВЫВОДЫ → ИСТОЧНИКИ. Каждый рисунок сопровождается текстом «что видно». Запуск:
`~/.cache/practice-report-venv/bin/python -I report/build_report.py`. Если у пользователя другой формат отчёта —
подстроить `report_lib.py`/`build_report.py` под его образец, а не наоборот.

**6. Завершение.** Остановить сервисы и фоновые процессы, сверить «хеш после» с «хешем до», проверить отчёт по чек-листу
PLAN.md (нет секретов на кадрах, нумерация сквозная, на все вопросы есть ответы) и коротко сообщить пользователю: что
сделано, отступления, что осталось на его решение, что нужно уметь объяснить на защите.

## Принципы (и почему)

- **Сначала изоляция, потом действия.** Работа идёт на личной машине, где есть рабочие настройки; их порча дороже любого
  дедлайна. Хеш до/после — дешёвое и однозначное доказательство, что ничего не сломано.
- **Не угадывать то, что знает пользователь**: ФИО, вариант, требования — спрашивать; согласие на установку/скачивание —
  явное, расплывчатое «делай аккуратно» согласием не считать.
- **Правда в отчёте.** Цифры, имена, статусы — из `notes/*.log`; отступления и ограничения называть прямо. Проверяющему это
  видно сразу, а студенту проще защищаться.
- **Воспроизводимость.** Скрипты `shots.py` и `build_report.py` лежат рядом с работой: при ошибке пересобирается одна часть.
- **Не грузить машину.** Не включать лишнее, если критерии методички этого не требуют; в конце всё останавливать.

## Быстрый старт (команды)

```bash
~/.claude/skills/practice-report/scripts/setup_env.sh                      # venv с python-docx/playwright/pymupdf
~/.cache/practice-report-venv/bin/python -I ~/.claude/skills/practice-report/scripts/pdf_to_text.py pr-N/методичка.pdf /tmp/pages
python3 ~/.claude/skills/practice-report/scripts/new_practice.py pr-N --no N \
    --student-surname Фамилия --student-short "Фамилия И.О." --group … --discipline "…" --supervisor "…"
# … план → окружение → работа → report/shots.py → report/build_report.py
```

Логотип на титульном листе необязателен: путь можно указать в `report/config.json` (`"logo"`), без него поле пропускается.

## Формат результата пользователю (в конце)

1. Ссылка на `.docx` (`report/<Фамилия>_ПР<N>_отчет.docx`) и число рисунков.
2. Что сделано по критериям методички (кратко, по пунктам).
3. Отступления от методички (3–6 пунктов).
4. Состояние окружения: что остановлено, «хеш до = после», как запустить заново.
5. Открытые вопросы и 3–5 тезисов для устной защиты.
