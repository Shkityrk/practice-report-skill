## Структура папки `pr-{N}`

```
pr-{N}/
├── PLAN.md
├── env.sh            # изолированное окружение (если работа может задеть рабочие настройки)
├── <каталоги работы по методичке>
├── notes/            # логи всех снятых команд (по одному на скриншот) + логи запусков
└── report/
    ├── config.json   # данные титульного листа
    ├── shots.py      # воспроизводимая съёмка скриншотов
    ├── build_report.py
    ├── screenshots/
    └── <Фамилия>_ПР{N}_отчет.docx
```

## Фазы

1. **Чтение и план** — методичка (+ картинки), образец отчёта → этот файл. Остановка: вопросы пользователю.
2. **Окружение** — установка/запуск, проверка изоляции (хеш рабочего конфига «до»).
3. **Реализация вручную** — прогнать всё один раз, починить ошибки методички, зафиксировать отступления.
4. **Съёмка** — `report/shots.py`: чистое состояние → этапы по порядку → кадры в `report/screenshots/`.
5. **Отчёт** — `report/build_report.py` → `.docx`; проверка по чек-листу.
6. **Завершение** — остановить кластеры/контейнеры/процессы, сверить хеш рабочего конфига «после», итог пользователю.

## Проверка перед сдачей (verification-before-completion)

- [ ] Все пункты T1…TO закрыты, у каждого есть рисунок/абзац в отчёте
- [ ] Нет секретов, токенов, адресов рабочих систем в `notes/*.log` и на картинках (grep)
- [ ] Рабочая конфигурация не изменилась (хеш «до» = «после»)
- [ ] Нет «висящих» процессов (проброс портов, веб-интерфейсы, контейнеры, серверы)
- [ ] Отчёт открывается, нумерация рисунков сквозная, подписи по образцу
