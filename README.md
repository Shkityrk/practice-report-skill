# practice-report

Универсальный skill для Claude Code, который превращает методичку в воспроизводимую практическую или лабораторную работу:

**методичка → план → изолированное выполнение → реальные скриншоты → отчёт `.docx`**.

Отчёт строится по результатам действительно выполненной работы. Команды, цифры и статусы берутся из логов и созданных файлов, а не придумываются для заполнения шаблона.

## Когда использовать

Skill срабатывает, когда пользователь просит:

- выполнить практическую или лабораторную работу;
- разобраться с работой по методичке;
- сделать работу `pr-N`;
- подготовить отчёт по ГОСТу или по образцу;
- добавить скриншоты в отчёт;
- собрать итоговый отчёт в Word (`.docx`).

Skill не привязан к конкретной дисциплине. Тема, вариант и требования к работе описываются в `PLAN.md` конкретной практики.

## Возможности

- читает методички PDF и извлекает текст и страницы-изображения;
- создаёт каркас работы с планом, окружением, заметками и генераторами;
- выполняет работу в изолированном окружении;
- фиксирует хеши рабочих файлов до и после выполнения;
- делает упорядоченные воспроизводимые скриншоты;
- маскирует секреты на кадрах;
- собирает отчёт `.docx` с титульным листом, содержанием, рисунками, таблицами, кодом, выводами и источниками;
- подстраивает оформление под переданный пользователем образец;
- завершает работу с проверкой процессов, секретов, нумерации и контрольных пунктов.

## Требования

- macOS или Linux;
- Python 3 с поддержкой `venv`;
- Claude Code;
- методичка в PDF или DOCX;
- папка практической работы;
- данные для титульного листа: ФИО, группа, дисциплина, руководитель и, если нужно, институт/кафедра;
- образец отчёта или отдельные требования к оформлению — желательно, но не обязательно.

Для генерации отчёта и скриншотов skill использует Python-пакеты:

- `python-docx` — создание Word-документа;
- `playwright` — автоматизация браузера и скриншоты;
- `pymupdf` — чтение PDF и сохранение страниц в PNG.

Системный Python не изменяется: зависимости устанавливаются в отдельное окружение `~/.cache/practice-report-venv`.

## Установка

### Установка вручную

Скопируйте каталог skill в каталог пользовательских skills Claude Code:

```bash
mkdir -p ~/.claude/skills
cp -R practice-report ~/.claude/skills/practice-report
```

Если репозиторий уже находится в нужном каталоге, копировать его не нужно. Проверьте наличие файла:

```bash
ls ~/.claude/skills/practice-report/SKILL.md
```

### Подготовка окружения

Запустите установщик из каталога skill:

```bash
~/.claude/skills/practice-report/scripts/setup_env.sh
```

По умолчанию окружение создаётся в `~/.cache/practice-report-venv`. Другой путь можно задать переменной `PRACTICE_VENV`:

```bash
PRACTICE_VENV="$PWD/.venv-practice-report" \
  ~/.claude/skills/practice-report/scripts/setup_env.sh
```

Установщик проверяет импорт всех необходимых пакетов. Браузер Playwright отдельно не скачивается: для скриншотов используется доступный браузер, найденный вспомогательными функциями skill.

## Инструкция для агента

Если агенту нужно установить этот skill в Claude Code, выполните следующие шаги.

1. Определите исходный каталог репозитория skill. В нём должны находиться `SKILL.md`, `references/`, `scripts/` и `templates/`.
2. Скопируйте каталог в пользовательский каталог skills:

   ```bash
   mkdir -p ~/.claude/skills
   cp -R /путь/к/practice-report ~/.claude/skills/practice-report
   ```

   Если каталог уже находится в `~/.claude/skills/practice-report`, этот шаг пропустите.
3. Проверьте, что обязательный файл доступен:

   ```bash
   test -f ~/.claude/skills/practice-report/SKILL.md
   ```
4. Установите зависимости skill в изолированное окружение:

   ```bash
   ~/.claude/skills/practice-report/scripts/setup_env.sh
   ```

5. Проверьте установку без использования системного Python:

   ```bash
   ~/.cache/practice-report-venv/bin/python -I -c \
     "import docx, playwright, pymupdf; print('practice-report: OK')"
   ```
6. Сообщите пользователю, что skill установлен, и укажите путь `~/.claude/skills/practice-report`.
7. Для запуска skill попросите пользователя передать методичку, папку работы, образец оформления и данные для титульного листа. Не угадывайте ФИО, группу и вариант.

Если установка зависимостей запрещена или отсутствует `python3`, остановитесь и сообщите агенту точную причину. Не устанавливайте пакеты в системный Python и не скачивайте браузеры или репозитории без явного разрешения пользователя.

## Быстрый старт

1. Положите методичку и материалы в папку работы.
2. Передайте Claude Code путь к методичке, папке и, если есть, образец отчёта.
3. После согласования плана skill создаст каркас работы:

```bash
python3 ~/.claude/skills/practice-report/scripts/new_practice.py pr-N \
  --no N \
  --student-surname Фамилия \
  --student-short "Фамилия И.О." \
  --group ИВТ-00 \
  --discipline "Название дисциплины" \
  --supervisor "Фамилия И.О."
```

1. Прочитайте методичку, заполните `PLAN.md` и подтвердите варианты, разрешения и ограничения.
2. Выполните работу в изолированном окружении.
3. Запустите скрипт скриншотов из `report/shots.py`.
4. Соберите документ:

```bash
~/.cache/practice-report-venv/bin/python -I report/build_report.py
```

Результат обычно находится в `report/<Фамилия>_ПР<N>_отчет.docx`.

Для предварительного разбора PDF можно использовать:

```bash
~/.cache/practice-report-venv/bin/python -I \
  ~/.claude/skills/practice-report/scripts/pdf_to_text.py \
  pr-N/методичка.pdf /tmp/practice-report-pages
```

## Рабочий процесс

Skill работает по этапам и не перескакивает через согласование плана.

### 0. Приём материалов

Методичка читается целиком. Если команды или код вставлены в PDF как изображения, страницы дополнительно просматриваются визуально. Также изучается лучший доступный прошлый отчёт и его генератор.

### 1. Планирование

Создаётся `PLAN.md` с:

- требованиями методички (`T1`, `T2`, …);
- окружением и рисками;
- известными ошибками или устаревшими местами методички;
- планом скриншотов;
- чек-листом готовности.

До выполнения уточняются ФИО, группа, вариант, недостающие материалы и разрешения на установки или скачивания. Значения для титульного листа не угадываются.

### 2. Окружение и безопасность

Сначала выполняется разведка только чтением, затем создаётся копия и хеш рабочих файлов. Установки, скачивания и действия за пределами папки работы выполняются только после явного разрешения пользователя.

### 3. Выполнение

Работа выполняется один раз полностью, с проверкой поведения, а не только признака «процесс запущен». Любое отступление от методички записывается в `PLAN.md` с объяснением причины.

### 4. Скриншоты

`report/shots.py` делает кадры в порядке методички: от чистого состояния до итогового результата. Команды запускаются с логом, секреты маскируются. Ключевые PNG просматриваются, неудачные кадры переснимаются точечно.

### 5. Сборка отчёта

`report/build_report.py` использует библиотеку `scripts/report_lib.py`. Типовая структура:

1. титульный лист;
2. содержание;
3. цель работы;
4. ход работы по этапам;
5. отличия от методички;
6. ответы на контрольные вопросы;
7. выводы;
8. источники.

Каждый рисунок сопровождается пояснением, что именно на нём видно.

### 6. Завершение

Останавливаются сервисы и фоновые процессы, сравниваются хеши до и после, проверяются отсутствие секретов на кадрах, сквозная нумерация и ответы на все вопросы.

## Результат для пользователя

В конце работы Claude сообщает:

1. ссылку на `.docx` и число рисунков;
2. что выполнено по требованиям методички;
3. отступления от методички и причины;
4. состояние окружения и результат сравнения хешей;
5. открытые вопросы и тезисы, которые нужно уметь объяснить на защите.

## Важные ограничения

- Не подставляйте чужие ФИО из старых отчётов: для другого человека нужны его данные и явная просьба пользователя.
- Не сообщайте «работа выполнена», если есть только сгенерированный текст без реального запуска.
- Не устанавливайте пакеты в системный Python.
- Не скачивайте репозитории, зависимости и браузеры без явного разрешения.
- Не включайте в отчёт или скриншоты пароли, токены, ключи и другие секреты.
- Логотип необязателен. Его путь можно указать в `report/config.json` через поле `logo`.

## Разработка и обновление skill

При изменении skill сохраняйте его контракт:

- `SKILL.md` содержит YAML frontmatter с полями `name` и `description`;
- имя `practice-report` должно совпадать с именем каталога;
- подробные инструкции, которые нужны не всегда, остаются в `references/`;
- повторяемые операции оформляются скриптами в `scripts/`;
- файлы, копируемые в новую работу, хранятся в `templates/`;
- не добавляйте в репозиторий локальные отчёты, логи, скриншоты и виртуальные окружения.

После обновления полезно проверить:

```bash
python3 -m py_compile scripts/*.py
bash -n scripts/setup_env.sh
```
